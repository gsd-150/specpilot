# W3 Part 2: Async API and Run Trace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add owner-authenticated asynchronous L1 runs, durable sanitized traces, correct terminal-state projection, and restart-safe interruption semantics.

**Architecture:** PostgreSQL stores run metadata and typed append-only events but never the question. FastAPI persists then enqueues an in-memory job; a leased worker invokes Part 1 and the existing answer chain. Reads enforce session ownership and derive `interrupted` from an expired lease before startup reconciliation persists it.

**Tech Stack:** Python 3.12–3.14, FastAPI, Pydantic 2, psycopg 3, AnyIO, HMAC-SHA256 session tokens, pytest/httpx ASGI.

## Global Constraints

- Depends on interfaces in `2026-08-11-w3-1-mcp-orchestration.md`.
- `provider_error` takes precedence over `VerifiedAnswer.verdict` when mapping an `AnswerOutcome`.
- Gate admission failures use `egress_blocked`, never `failed` or `evidence_insufficient`.
- An expired queued/running lease is observable as `interrupted` even if no process wrote at death time.
- `GET /runs/{run_id}` returns the same 404 shape for unknown and foreign-owned runs.
- No query, excerpt, candidate body, provider response, credential, secret, or local path is persisted or returned.
- No silent provider retry and no W4 checkpoint/recovery implementation.
- Before database work, run `dropdb --if-exists specpilot_w3_api_test`, `createdb specpilot_w3_api_test`, `dropdb --if-exists specpilot_w3_e2e_test`, and `createdb specpilot_w3_e2e_test`; never substitute `specpilot_live`. Before Task 6, start the isolated vector service with `docker run --rm -d --name specpilot-w3-api-qdrant -p 127.0.0.1:6334:6333 qdrant/qdrant:v1.12.4`.
