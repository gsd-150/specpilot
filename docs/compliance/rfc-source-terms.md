## summary

依据 2026-08-07 冻结的 BCP 78（RFC 5378）、IETF Trust license-info 与 Trust Legal Provisions 5.0 三份快照。使用者一侧的权利由 TLP 界定，BCP 78 规范的是贡献者向 IETF Trust 授予的权利，二者不可互相替代。

TLP §3.c 对 IETF 标准流程**之外**的使用预先授予非独占、免版税、全球范围的许可，无需逐次申请：§3.c.i 允许完整且未经修改地复制、发布、展示与分发；§3.c.iii 允许复制、发布、展示与分发**未经修改的部分片段**，但附两项条件——(x) 每个片段须明确归属 IETF 并标明取自哪一份 RFC；(y) 当复制的是 RFC 正文的实质性部分，且无论如何超过五分之一时，原文中全部 IETF 标记、法律声明与作者信息须一并包含。TLP §3.d 明确不授予在标准流程之外修改文档或其片段的许可，翻译与 Code Component 除外。TLP §5.a 与 BCP 78 §5.5 均声明不含任何专利许可。RFC 9110 与 RFC 9112 均于 2022 年 6 月发布（STD 97 与 STD 99），各自版权声明指向 BCP 78 及发布之日生效的 TLP。

本项目据此不提交、不发布 RFC 正文，原始 `.txt` 与 `.xml` 保留在私有受限目录，仓库只接收实现、测试与脱敏记录。出站只允许受限摘录，受 `default-v1` 强制上限约束。摘录的未修改性由契约机械保证：`EvidenceExcerpt.quote_hash` 必须等于该片段 UTF-8 字节的 SHA-256，任何改动都会在构造时被拒绝。每次出站载荷携带 `VersionMetadata`，其中的 `document_id` 与 `document_version` 标明片段取自哪一份 RFC 的哪个版本。本项目不主张已满足 §3.c.iii 对公开复制场景规定的全部形式要件，仅记录上述机制与该条款的对应关系。

## uncertainty

1. §3.c.iii(y) 的五分之一阈值以整份文档为计量对象，而本项目的出站上限以 token 与字节计。两套计量口径如何换算，条款未作规定；因此"累计摘录是否已触及该阈值"无法仅凭现有上限值判定。

2. §3.c.iii 授权的行为是复制、发布、展示与分发。将受限摘录发送至第三方 API 供模型处理，是否落入这四者的语义范围，条款未直接涵盖；本评估不将其推定为已获许可，也不推定为被禁止。

3. §3.d 在标准流程之外不授予修改许可，而检索管线会对源文档做分块与规范化。何种程度的处理构成条款意义上的"修改"，TLP 未作界定；本项目仅能保证外发片段本身与源字节逐字节一致，无法据此断言管线内部的中间表示不构成修改。

## 与 3GPP 源条款的关系

3GPP/ETSI 的立场是「默认保留权利，复制须事先取得明示同意」；IETF 的立场是「预先授予的公开许可，附归属与五分之一条件」。方向相反。这不改变本项目的出站机制，只改变该机制所依据的条款前提。
